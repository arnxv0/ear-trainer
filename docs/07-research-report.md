# Build the song corpus first, then train transfer

The biggest improvement available is not a better drill. It is a free, already aligned corpus: Sheet Sage's `Hooktheory.json.gz` gives **16,373 usable melody segments with YouTube video IDs, key and mode, notes in beats, chords, and a per-beat beat-to-seconds alignment**, all in a 20 MB file under CC BY-NC-SA 3.0, which is fine for personal use. That one file turns modes 2 and 3 from a manual annotation chore into a few hundred lines of Python, and its artist-stratified test split hands you a ready-made pool of held-out songs for mode 3. The second big lever is pedagogical. The research is consistent that drill accuracy does not carry over to real songs on its own, so the app should measure and train transfer directly: an explicit find-the-tonic step, multi-note phrases instead of single notes, a key context that fades away, and a separate "real song" score that drill scores cannot mask. Mode 1 (piano-roll drills in key context) is a solved, commodity problem; Functional Ear Trainer, Sonofield and ToneSavvy already do it well. The open gap in the market, scale-degree melody drills tied to real YouTube clips, is exactly modes 2 and 3, and that is where a solo builder's time pays off. The hard technical limits are YouTube's: clips snap to keyframes (up to about 2 s early), the player must stay visible at 200x200 or more, and downloading audio for stem separation or pitch tracking is prohibited, so all analysis has to come from symbolic data rather than the recordings.

## One 20 MB file already contains modes 2 and 3

Each entry in `Hooktheory.json.gz` is keyed by HookTheory ID and looks like this (field names verbatim, from the Adam Lambert entry `qveoYyGGodn`) ([sheetsage-data](https://github.com/chrisdonahue/sheetsage-data/raw/refs/heads/main/hooktheory/Hooktheory.json.gz)):

```
{
 "tags": ["NO_SWING","AUDIO_AVAILABLE","USER_ALIGNMENT","REFINED_ALIGNMENT","MELODY","HARMONY"],
 "split": "TRAIN",
 "hooktheory": {"id","artist","song","annotators":[...], "urls":{"artist","song","clip"}},
 "youtube": {"id":"X1Fqn9du7xo","url":"https://www.youtube.com/watch?v=X1Fqn9du7xo","duration":225.36},
 "alignment": {"swing":"STRAIGHT",
               "user":   {"beats":[0,44],"times":[51.85,80.21]},
               "refined":{"beats":[0,1,...,44],"times":[51.8487,52.4887,...,80.2387]}},
 "annotations": {
   "num_beats": 44,
   "meters": [{"beat":0,"beats_per_bar":4,"beat_unit":4}],
   "keys":   [{"beat":0,"tonic_pitch_class":2,"scale_degree_intervals":[2,2,1,2,2,2]}],
   "melody": [{"onset":1,"offset":2,"octave":0,"pitch_class":11}, ...],
   "harmony":[{"onset":0,"offset":2,"root_pitch_class":7,"root_position_intervals":[4,3],"inversion":0}, ...]
 }
}
```

Three things matter here. Melody is stored as **absolute pitch class plus a relative octave**, with `onset` and `offset` in fractional beats, so the scale degree is `(pitch_class - tonic_pitch_class) mod 12`. In the example (D major), the first notes B, A, E, F# come out as 6, 5, 2, 3, which matches the Raw file's native scale-degree values. The `scale_degree_intervals` array encodes mode: `[2,2,1,2,2,2]` is major, `[2,1,2,2,1,2]` natural minor, `[2,2,1,2,2,1]` Mixolydian, `[2,1,2,2,2,1]` Dorian. And seconds come from **linear interpolation of `alignment.refined.beats` against `alignment.refined.times`**, which is exactly what Sheet Sage's own notebook does with `scipy.interpolate.interp1d(..., kind='linear', fill_value='extrapolate')`, with MIDI pitch computed as `pitch_class + (5 + octave) * 12` ([Dataset.ipynb](https://github.com/chrisdonahue/sheetsage/blob/main/notebooks/Dataset.ipynb)). The README recommends keeping entries tagged `AUDIO_AVAILABLE` and `MELODY` and dropping `TEMPO_CHANGES` ([sheetsage README](https://github.com/chrisdonahue/sheetsage)).

The full conversion fits on one screen:

```python
import gzip, json
from scipy.interpolate import interp1d

DEG = {0:"1",1:"b2",2:"2",3:"b3",4:"3",5:"4",6:"#4",7:"5",8:"b6",9:"6",10:"b7",11:"7"}
NEED, DROP = {"MELODY","AUDIO_AVAILABLE","REFINED_ALIGNMENT"}, {"TEMPO_CHANGES","KEY_CHANGES"}

out = []
for hid, e in json.load(gzip.open("Hooktheory.json.gz")).items():
    tags = set(e["tags"])
    if not NEED <= tags or tags & DROP:
        continue
    a, ann = e["alignment"]["refined"], e["annotations"]
    to_sec = interp1d(a["beats"], a["times"], kind="linear", fill_value="extrapolate")
    key = ann["keys"][0]
    tonic = key["tonic_pitch_class"]
    notes = [{
        "t0": round(float(to_sec(n["onset"])), 3),
        "t1": round(float(to_sec(n["offset"])), 3),
        "deg": DEG[(n["pitch_class"] - tonic) % 12],   # do-based: minor tonic is still 1
        "midi": n["pitch_class"] + (5 + n["octave"]) * 12,
    } for n in ann["melody"]]
    out.append({"id": hid, "yt": e["youtube"]["id"], "split": e["split"],
                "artist": e["hooktheory"]["artist"], "song": e["hooktheory"]["song"],
                "start": float(to_sec(0)), "end": float(to_sec(ann["num_beats"])),
                "tonic": tonic, "mode": key["scale_degree_intervals"], "notes": notes,
                "harmony": ann["harmony"]})
json.dump(out, open("corpus.json", "w"))
```

The degree table is relative to the tonic regardless of mode, which gives do-based minor (minor tonic stays 1, its third is b3) for free. Use the companion `Hooktheory_Raw.json.gz` if you want HookTheory's own enharmonic spelling, since its `json.notes[]` entries store melody natively as `sd` strings with `octave` and 1-indexed beats, and its chords are already in functional form (root as scale degree, `applied`, `borrowed`) ([Raw file](https://github.com/chrisdonahue/sheetsage-data/raw/refs/heads/main/hooktheory/Hooktheory_Raw.json.gz)).

The filtered set is **about 10,098 unique songs and roughly 101 hours, median segment about 20 s**, split by mode into 7,977 major, 6,736 minor, 628 Mixolydian and 624 Dorian, with Lydian, Phrygian and Locrian making up the tail. The `split` field is an 8:1:1 train, valid and test partition **stratified by artist** ([sheetsage README](https://github.com/chrisdonahue/sheetsage)), which is the cleanest possible definition of "unknown songs" for mode 3: drill on TRAIN, test on TEST, and you will never be tested on an artist you drilled. Every entry carries a `youtube` object (15,007 unique video IDs), confirmed directly from the file.

Know the failure modes before you trust the timestamps. The refined alignment snaps beats to madmom's detected downbeat, and in the authors' listening test it improved 95 of 100 segments, with the main failure being **a wrong downbeat, which shifts everything by a bar** ([Donahue et al., arXiv 2212.01884](https://arxiv.org/abs/2212.01884)). Note offsets are heuristic, matching annotation for 89% of notes ([ar5iv](https://ar5iv.labs.arxiv.org/html/2212.01884)). Link rot is unmeasured: the data dates from about 2022 and no attrition figure is published, and embed blocks or region locks in India are not in the dataset at all. Check availability yourself from your own machine with YouTube's oEmbed endpoint and cache the result. Indian repertoire is essentially absent (only A. R. Rahman's "Jai Ho" and "Roja" turned up), so Bollywood songs mean self-annotation: a small editor that stores YouTube ID, tonic, and tapped notes in the same schema.

The alternatives are clearly worse for this loop. Popular Hooks repackages the same HookTheory data into 38,694 sections with lyrics, genre and language, but stores sync as fractions of video duration with only start and end points and no license on its card ([HF dataset card](https://huggingface.co/datasets/NEXTLab-ZJU/popular-hook)), so use it at most as a metadata join on HookTheory ID. DALI has 5,358 YouTube-linked songs with vocal notes but no key, crowd-sourced notes, and documented alignment errors ([DALI GitHub](https://github.com/gabolsgabs/DALI)). MIR-ST500 has 500 mostly Mandarin songs with no key and no license file ([singing_transcription_ICASSP2021](https://github.com/york135/singing_transcription_ICASSP2021)). POP909 has clean melody and key in seconds but no audio links at all ([POP909-Dataset](https://github.com/music-x-lab/POP909-Dataset)).

## Context helps a little; transfer is where training fails

The evidence for "functional beats intervals" is weaker than app marketing suggests. In the best controlled study, a major-scale context improved interval discrimination by **0.47 d′** and a cadence-like context by **0.28 d′** over no context, but simply repeating the test pitch did as well as the scale, and the authors read the effect as priming rather than better interval representations ([Graves & Oxenham 2017](https://www.frontiersin.org/articles/10.3389/fpsyg.2017.01753/full)). Theorists still argue that isolated interval skill connects poorly to hearing in tonal context ([Chenette 2021, MTO](https://www.mtosmt.org/ojs/index.php/mto/article/view/613/149)), but no head-to-head adult training trial settles it. The honest conclusion: key context is the right frame, it is not magic, and the real problem lies elsewhere.

That problem is transfer. A learner who spent about four months on intensive scale-degree drills could name degrees played alone but not inside songs ([Improvise for Real](https://www.improviseforreal.com/?p=39716)), and forum users say the same about apps generally: scoring points did not help them pull melodies from dense recordings ([JustinGuitar community](https://community.justinguitar.com/t/most-effective-ear-training-method/260153)). Chenette's explanation is working memory: listeners hold about **3 to 4 chunks**, capacity is likely fixed by adulthood, so training must make encoding more efficient through chunking ([Chenette 2021](https://www.mtosmt.org/ojs/index.php/mto/article/view/613/149)). Single-note drills do not train chunking. In real songs nobody plays a cadence first either, and practitioners treat finding the tonic as a separate prerequisite skill ([UEN Pressbooks aural skills research list](https://uen.pressbooks.pub/auralskills/back-matter/aural-skills-pedagogy-research/); [Musical U](https://www.musical-u.com/training/roadmaps/play-melodies-by-ear-solfa/)). Pop tonics can also be genuinely ambiguous in loop-based songs ([Marvin 2021, MTO](https://mtosmt.org/issues/mto.21.27.2/mto.21.27.2.marvin.pdf)), so mode 3 should grade degrees relative to the tonic you chose and score tonic-finding separately.

Practice scheduling has stronger evidence. Interleaving categories beat blocking when no reference aids were available, and **most learners wrongly believed blocking worked better** ([Wong et al. 2021](https://ink.library.smu.edu.sg/soss_research/4316)). Random groupings matched confusability-ordered ones while taking less time (1.73 vs 2.24 hours), and a hard 90% mastery gate worked but frustrated learners ([Blombach et al.](https://journals.ou.edu/jmtp/article/download/834/1675/1665)). Practice with feedback plus passive exposure to the same sounds took interval discrimination from **69% to 88% in 3 days**, while exposure without practice did nothing ([Little et al. 2018 summary](https://featuredcontent.psychonomic.org/perfect-unison-or-perfect-fourth-practice-makes-perfect-only-with-exposure-during-musical-interval-training/)), and the exposure benefit shrank when given 15 minutes after practice and vanished at 4 hours ([Wright et al. 2010](https://experts.arizona.edu/en/publications/enhancing-perceptual-learning-by-combining-practice-with-periods-/)). That translates directly into design: interleave by default, give feedback on every drill trial, keep mode 3 feedback-free as the honest measure, and play a "listen-through" of the song clip with degrees highlighted right after a drill set.

Your note-name buttons deserve some pushback. Comparative studies found no solmization system clearly better than another ([Lorek & Pembrook, JMTP](https://journals.ou.edu/jmtp/article/download/723/1564/1554)), so C, D, E is defensible. But in a cross-cultural cadence-then-degree test, more than two-thirds of Polish conservatory students scored 90% or better versus fewer than one-tenth of Japanese students, a gap the author ties to early fixed-label and absolute-pitch habits ([Miyazaki 2019](https://www.human.niigata-u.ac.jp/~psy/miyazaki/Papers/Miyazaki2019-12-14.pdf)), and r/eartraining users report "can't stop hearing everything in C major" ([r/eartraining mirror](https://lr.sudovanilla.org/r/eartraining)). Absolute names make you compute "which note in this key," which is the mediation step functional training is trying to remove. Keep the note names, but print the degree number on every button and rotate the key every trial or set.

Two smaller findings shape mode 1. Scale-degree "color" depends on the local chord underneath it, not just global stability ([Arthur 2018 summary](https://sonicfield.org/library/a-perceptual-study-of-scale-degree-qualia-in-context)), so drilling only over a static I chord or drone teaches a narrow skill; the dataset's `harmony` field lets you ask "degree of the note over this chord" for real. And pitch-relation learning generalizes across register in the lab ([Zatorre et al. 2012](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2012.00544/full)), while descending intervals are harder than ascending ones (about 59 to 64% vs 74 to 78%) ([Blombach et al.](https://journals.ou.edu/jmtp/article/download/834/1675/1665)), so randomize the target's octave and include targets below the tonic. No study tests a drone against a cadence, a context-fading schedule, or spaced repetition for scale degrees specifically; those recommendations are reasoned from adjacent evidence.

Expect weeks, not days, for single-degree recognition in context and months for real songs. Musical U says the pentatonic recognition phase alone "could take several weeks to really master" ([Musical U](https://www.musical-u.com/training/roadmaps/play-melodies-by-ear-solfa/)), and lab learners split into fast and slow groups that ended at the same level ([Zatorre et al. 2012](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2012.00544/full)). That argues for adaptive pacing and for a dashboard that shows drill accuracy and real-song accuracy side by side.

## Real-song melody drills are an open gap in existing apps

Key-context drills are everywhere. Functional Ear Trainer plays a chord and asks for the tone's function ([App Store](https://apps.apple.com/app/id1088761926)); Sonofield uses a drone and lets you turn the drone and cadence off ([App Store](https://apps.apple.com/us/app/sonofield-ear-trainer/id6740409139)); ToneSavvy offers custom degree sets, numbers-only labels, keyboard shortcuts, and "Descend/Ascend to Root" resolution playback ([ToneSavvy](https://tonesavvy.com/music-practice-exercise/220/functional-solfege-scale-degree-ear)). Mode 1 adds nothing new on its own, so keep it lean and spend effort on what feeds modes 2 and 3.

Real recordings are rare. Hooktheory Chord Crush drills chords from real YouTube audio using TheoryTab data, with an adaptive rating and chord previews that fade as the rating rises, and people pay $49 to $79 a year for it ([Chord Crush](https://www.hooktheory.com/chordCrush)). OpenEar, open source and built on Tone.js, has a YouTube "chord progressions in real songs" exercise (Android only) plus a "Notes with Chords" exercise that asks for the note's degree and the chord's degree together ([OpenEar GitHub](https://github.com/ShacharHarshuv/open-ear)). Neither does scale-degree melody drills on real clips, and nothing found tests you on songs you have not drilled. Your mode 3 targets the single most common complaint in the space.

The complaints map neatly to fixes. Complete Ear Trainer users report "Easy" jumping straight to hard material and near-chance scores for days before quitting, while its developer defends playing the cadence once per six questions to train key retention ([AppsHunter reviews](https://appshunter.io/ios/app/complete-ear-trainer/id1012455471/reviews)). Chord Crush's fading previews resolve that debate better than an on/off toggle. EarMaster critics find generated chromatic melodies "random and unmusical" ([EarMaster forum](https://www.earmaster.com/forum/viewtopic.php?p=38483)), which corpus-mined patterns avoid. EarMaster and Intonote both turn confusion stats into targeted practice ([EarMaster](https://earmaster.com/products/ear-training-sight-singing/earmaster-software.html); [Intonote](https://mwm.ai/apps/intonote/6759245944)). Meludia recommends about 20 minutes a day and warns that more than 30 risks overload ([Meludia FAQ](https://meludia.com/en/im-not-making-any-progress-what-should-i-do)). Leaderboards and coins are worth skipping in a single-user tool.

## YouTube's rules force symbolic analysis and a careful clip engine

The IFrame API can play "bars 17 to 21," with caveats. `seekTo` and the `start` parameter go to the nearest keyframe, so playback can begin **up to about 2 s early**, and `end` is an integer counted from the start of the video ([player parameters](https://developers.google.com/youtube/player_parameters); [IFrame API reference](https://developers.google.com/youtube/iframe_api_reference)). Build loops yourself: poll `getCurrentTime()` every 50 to 100 ms while playing and `seekTo(start, true)` when you pass the segment end. `setPlaybackRate` is not guaranteed, rounds unsupported values toward 1, and resets on every load or cue, so reapply it after loads and listen for `onPlaybackRateChange` ([IFrame API reference](https://developers.google.com/youtube/iframe_api_reference)). Start clips 1 to 2 s early and highlight the target note with your own timer, since the docs give no figure for `getCurrentTime()` resolution. On mobile, pass `playsinline: 1`, call `playVideo()` synchronously inside the tap handler, and handle `onAutoplayBlocked` with a tap-to-play button.

The policy constraints are firm. The player must be at least 200x200 and unobscured; you may not isolate audio, play from a background player, or download and store content without written approval ([YouTube API Developer Policies](https://developers.google.com/youtube/terms/developer-policies)), and the ToS bars downloading and automated access ([YouTube ToS](https://www.youtube.com/static?template=terms)). That rules out the tempting pipeline of yt-dlp, then Demucs vocals, then pitch tracking. It also does not matter much, because the HookTheory notes already give you the melody. Put your piano roll and answer buttons beside or below the player, never over it.

For the synthesized side, smplr is the current choice: SplendidGrandPiano plus General MIDI soundfonts for timbre variety, from the same author as the superseded soundfont-player ([smplr GitHub](https://github.com/danigb/smplr)). Its samples sit on rate-limited GitHub Pages, so self-host or cache them, and schedule cadences against `AudioContext` time rather than `setTimeout`. On iOS, Web Audio goes silent with the ringer switch off; the workaround is to play a looping silent `<audio>` element in the same tap that resumes the context ([Audjust](https://www.audjust.com/blog/unmute-web-audio-on-ios)). If you add sing-back, pitchy (McLeod method, returns pitch and a 0 to 1 clarity value, 0BSD) is enough for grading one note against a known target ([pitchy GitHub](https://github.com/ianprime0509/pitchy)); fold the result to the target's octave, gate on clarity, take a median over a few hundred milliseconds, and disable echo cancellation, noise suppression and auto gain. Neural trackers like SwiftF0 score better under noise ([SwiftF0, arXiv 2508.18440](https://arxiv.org/html/2508.18440v1)), but they are an upgrade path, not a starting point. One caution from the evidence: singing a pattern right before a dictation lowered scores ([Buonviri 2015, JRME](https://journals.sagepub.com/doi/10.1177/0022429415570754)), so keep singing as a practice mode, not a warm-up before mode 3.

## Tagging and difficulty are cheap; calibration is the real work

Once every note is a `(degree, onset, duration)` tuple, most concept tags are a few lines each. Count scale-degree 2 to 4 grams (`5-6-5`, `3-2-1`, `7-1`) and keep the distinctive ones per song by TF-IDF across the corpus; record the degree of notes on strong beats and phrase ends ("lands on 3"); compute the step and leap ratio (steps 2 semitones or less, large leaps 7 or more); flag chromatic degrees like `b7` in major or `#4`; and mark chord tones versus non-chord tones from the `harmony` field. These tags do double duty: they let you link a mode 1 drill to clips containing that exact motif, and they let you build mode 2 sets around a concept ("songs that resolve 7 to 1").

For difficulty, combine surface features (range, mean and max interval, leap ratio, chromatic fraction, notes per second, distinct degrees) with **information content**, how surprising each note is given the corpus. IDyOM is the standard model and py2lispIDyOM can drive it from Python ([py2lispIDyOM, JOSS](https://joss.theoj.org/papers/10.21105/joss.04738.pdf)), but it wraps Common Lisp, and the newer Python options (GraphIDyOM, AMADS, melody-features) are early-stage ([AMADS PyPI](https://pypi.org/project/amads/)). A smoothed order-3 n-gram model over degrees, trained on the HookTheory TRAIN split, is a serviceable surprisal proxy in about 50 lines. No published study validates any ear-training difficulty formula against learner performance, so treat the weighted sum as a prior and let your own answers correct it: an Elo-style rating per item and per user, updated after every trial, gives you calibrated item difficulty and a skill estimate that drives the scaffolding. That is the same adaptive mechanism Chord Crush uses, applied to melody.

## Conclusion

The project's real asset is not the piano roll; it is the bridge between drills and recordings, and the data to build that bridge already exists in a schema close to what the app needs. That changes the build order: the corpus pipeline and clip engine come before any polish on mode 1, because they are prerequisites for the only part of the app no one else offers. It also changes what "progress" means. A high score on cadence-plus-note drills is weak evidence of the target skill, so the app should treat held-out real-song phrase accuracy, with tonic found unaided, as its north-star number and let everything else, from context fading to item difficulty, adapt to move it.

The remaining uncertainties are empirical and cheap to resolve on your own machine: how many of the 15,007 video IDs still play and embed in India, how much `getCurrentTime()` jitter you see, and whether the corpus-derived difficulty prior matches your own error patterns after a few hundred trials. Logging every trial from day one (item, degree, response time, scaffold level, correct or not) is the single habit that makes all three answerable, and it doubles as the training data for calibrating the app to you.
